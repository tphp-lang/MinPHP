# 闭包

闭包字面量、捕获语义与生成结构。`callable` 类型 = 闭包 / C 函数指针（双字 `{fn, env}`）。

## 1. 语法

```php
function (int $v) use ($base, &$acc): int { return $v + $base; }   // 块体 + use
fn (int $v): int => $v + $base;                                    // 箭头糖，自动按值捕获
```

- **`use` 子句位置**：参数列表之后、返回类型**之前**（与 PHP 一致）。
  写成 `): T use (...)` 报编译错 `期望 '{'，得到 'use'`
- **捕获列表是裸变量**（可加 `&` 表示按引用），**不接受类型标注**；
  签名类型由外层变量的声明类型决定
- `fn` 是解析期糖：包装为单 `return` 块体的 `function` 闭包（无 `use` 子句）
- 参数/返回类型与普通函数一致；省略返回类型时非箭头闭包为 `void`
- 调用：`$f(1, 2)`；管道右侧可直接用：`8 |> $f()`（左值插入首参）

## 2. 值表示

```c
typedef struct {
    void *fn;    // 生成的 thunk，末参数为环境指针
    void *env;   // 捕获环境 / 引用盒子（tphp_env_alloc 登记）
} Callable;
```

`callable` 是**值类型**（双字结构体），可赋给变量、传参、返回、存容器；
`null` 表示空 callable（`{0}`）。

## 3. 捕获语义

### 3.1 按值捕获 `use ($a)`

捕获时**复制**当前值进环境。闭包体内修改捕获的变量不影响外层（环境是独立副本）；
捕获的堆值（对象/数组/接口）在环境析构时递减引用。

### 3.2 按引用捕获 `use (&$a)`

内外**共享存储**：闭包内写 `$a` 外层可见，反之亦然。经**堆盒子**实现（见 §3.5）。

### 3.3 箭头函数 `fn`

自动按值捕获**直接外层**作用域中出现的变量（无需 `use`）；无引用捕获能力。
捕获发生在闭包**创建时**（值快照）。

### 3.4 `$this`

类方法内的闭包可用 `$this`（自动进入环境，字段访问照常）；
生成侧重映射为 `((ENV*)__env)->self`。

### 3.5 引用捕获 = 堆盒子

`use (&$a)` 使 `$a` 的存储**提升为堆盒子**：外层与闭包内都改为解引用访问。

- 盒子由 `tphp_env_alloc` 分配（零初始化）并登记，进程退出统一回收
- **预扫描**：编译器先收集函数体内全部 `&$var` 捕获名，声明落地时即按盒子处理
  （避免"先按值用、后被引用捕获"的存储不一致）
- 未初始化的盒子读为类型零值（与未初始化堆变量一致）
- 逃逸安全：盒子生命周期独立于声明作用域，闭包可存留于容器 / 返回给调用方

### 3.6 环境生命周期

闭包环境与引用盒子在**创建时分配并登记**，随进程退出统一回收（`atexit`）：

1. 先执行各环境析构（`dtor`）：递减捕获的堆值引用（对象/数组/接口），
   并释放按值捕获的堆值自身持有
2. 再释放环境块

这与字符串 bump 池同属"v0.2 不主动回收"的取舍：闭包值本身在进程期存活，
其**捕获的堆值**引用计数正确（不泄漏被捕获对象）。

### 3.7 闭包体变量访问门

闭包体内的变量访问受严格门控（`gateClosureVar`）：

| 情形 | 结果 |
|---|---|
| 本闭包的参数 / 局部 / 已解析捕获 | ✅ 正常访问 |
| 箭头闭包访问**直接外层**变量 | ✅ 自动按值捕获（§3.3） |
| `function` 闭包访问外层变量而未 `use` | ❌ 编译错误：`闭包体内的变量 $x 必须 use (...) 捕获` |
| **跨闭包边界**访问（访问非直接外层的变量） | ❌ 编译错误：`嵌套闭包只能捕获直接外层函数/闭包的变量` |
| 已被引用捕获的变量再被引用捕获 | ❌ 编译错误（非本作用域声明，见 `isCapture` 标记） |
| **闭包字面量嵌在另一闭包体内**（嵌套闭包） | ❌ v0.3 已知缺陷：前端接受，但内层 thunk 定义生成在外层函数体内 → C 编译报 `invalid storage class for function 'tphp_closure_N'`（待修，见 §6） |

## 4. 生成结构

| 产物 | 节 | 说明 |
|---|---|---|
| 捕获环境 struct | typedefs | 每个闭包字面量一个（字段 = 捕获项 / `self` / `_box` 指针） |
| thunk | closures | 闭包体实现，末参数为环境指针（原型进 protos） |
| 环境 dtor | closures | 递减捕获的堆值引用 |
| 创建点 | 语句表达式 | `tphp_env_alloc` → 填充捕获 → `(Callable){thunk, env}` |

闭包体内的变量重映射由 `capCtx` 栈完成：

```
按值捕获名  → ((ENV*)__env)-><field>
引用捕获名  → (*((T*)((ENV*)__env)-><field>_box))
$this      → ((ENV*)__env)->self
```

## 5. 与 C 互操作（`c_fn`）

`c_fn($closure)` 把闭包转为 C 回调函数指针（trampoline 转发，约定 C 回调尾参
`void* userdata` 携带环境）——详见 `doc/phpc.md`。

## 6. 错误与边界（测试对应）

| 用例 | 覆盖 |
|---|---|
| `20_closure` | 基本闭包：按值/引用捕获、`$this`、管道调用、容器存放 |
| `21_closure_err` | 闭包相关错误路径 |
| `22_invoke_nosig` | 变量不可调用（未赋闭包，签名不可推导） |
| `23_closure_use_required` | `function` 闭包未 `use` 访问外层变量 → 编译错误 |
| `27_cfn_callback` | `c_fn` → C 回调 |

**边界**：闭包签名经变量传递（`$f = fn...; $f(1)` 按标注签名校验）；
未赋值的 `callable` 变量调用报"需赋值闭包以推导签名"。

**`callable` 调用的作用域规则**（v0.3 实测）：

- 普通函数 / 方法体内：`callable` **形参**与有赋值的**局部变量**都可直接调用 ✅
- `callable` 变量 / 形参传给 `c_fn` ✅（trampoline 从变量取签名）
- **闭包体内**：`use` 捕获的 callable ✅ 可调用——签名随捕获跨闭包边界传递
  （`use($cb)` 时把外层 symbol 的 `closureSig` 带进捕获 symbol）；
  **本闭包的 `callable` 形参** ✅ 可调用——签名经调用点回填跨两遍检查存活
  （调用点实参的闭包签名流入形参 symbol，pass 2 闭包体可见；用例 `66_closure_callable_use`）。
  已知顺序边界：若**闭包字面量的检查先于调用点所在的函数体**（如被调函数声明在
  调用函数之前且跨文件），pass 1 签名尚未流到，仍报
  `变量 $x 不可调用（需赋值闭包以推导签名）`——调整声明顺序即可规避
  过渡写法：回调逻辑写进 c_fn 闭包体本身（只用 C 调用与字面量），
  或拆为**全局函数** / `ClassName::method()` 在闭包内调用（两者实测 OK；
  `self::method()` 在闭包内静默返回 0，见 §6.1 缺陷 ③）

### 6.1 嵌套闭包（v0.3 实测矩阵）

闭包字面量出现在**另一闭包体内**时，前端全部接受，但生成的 C 把内层 thunk
定义放在外层 thunk 函数体内（C 不允许函数内定义函数）→ 四种组合全部
C 编译失败。修法方向：内层 thunk 定义提升到文件作用域（声明已在 protos，
只差定义落点）。

| 组合 | 前端 | C 编译 |
|---|---|---|
| 方法内一层闭包（function / fn） | ✅ | ✅ |
| function 内嵌 function | ✅ | ❌ `invalid storage class for function 'tphp_closure_N'` |
| function 内嵌 fn | ✅ | ❌ 同上 |
| fn 内嵌 function | ✅ | ❌ 同上 |
| fn 内嵌 fn | ✅ | ❌ 同上 |

过渡写法：内层闭包提升为**全局函数**或**类静态方法**（经 `ClassName::m()`
调用；`self::` 见缺陷 ③）。

**闭包相关待修缺陷（v0.3，均经最小复现实测）**：

1. **嵌套闭包 C 编译失败**——如上表（Gen：内层 thunk 定义未提升到文件作用域）
2. ~~闭包内调用 `callable` 报错~~ **已修复**：`use` 捕获的（捕获 symbol 携带外层
   `closureSig`）与本闭包 `callable` 形参的（调用点回填 + 闭包 FnSymbol 按 AST
   节点记忆化跨两遍存活）均可调用，用例 `66_closure_callable_use`；
   残留边界：被调体先于调用点检查的声明顺序（见 §6 作用域规则）
3. **闭包内 `self::method()` 静默返回 0**——`self::` 调用表达式未生成，
   thunk 落成 `__rv = 0 /* unreachable */`（Gen：闭包上下文丢失 self 解析）。
   最危险的一类：**静默出错值而非报错**。规避：用 `ClassName::method()` /
   全局函数；`$this->field` 访问不受影响（§3.4）

### 6.2 闭包变量不要标注 `c.ptr`

`c_fn` 依赖变量**推断**出的闭包签名；对承接闭包字面量的变量显式标注
`c.ptr` 会抹掉签名，报 `初始化类型不匹配：期望 c.ptr，得到 callable`：

```php
c.ptr $f = fn (int $v): int => $v + 1;   // ❌ 前端报错
$f = fn (int $v): int => $v + 1;         // ✅ 先推断签名
c.ptr $p = c_fn($f);                     // ✅ c_fn 返回值标注 c.ptr 合法
```

详见 `doc/phpc.md` c_fn 节。
