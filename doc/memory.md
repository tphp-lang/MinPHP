# 内存安全模型

TinyPHP 的内存安全分三层：**安全核心**（纯 TinyPHP 代码，构造即安全）、
**自动回收**（编译器引用计数插桩，开发者零感知）、**phpc unsafe 边界**
（显式 C 互操作，规则明确、默认安全）。

开发者**不需要**也没有任何手段手动管理 TinyPHP 对象的内存——
没有 free、没有 unset、没有指针运算。

## 一、安全核心（不涉及 C 互操作时）

| 保证 | 机制 |
| ---- | ---- |
| 无悬垂指针 | 引用计数归零才释放；编译器保证每个引用都有计数 |
| 无 double-free | 每个所有权点只 decref 一次（编译器插桩，非人工） |
| 无未初始化读 | 变量声明即零初始化（null/{0}/0/空串） |
| 越界即中止 | 数组/字符串下标越界 → panic |
| 空指针即中止 | 对象/接口/指针解引用前插空指针 panic |
| 类型精确 | 无 mixed、无运行期类型混淆；每个值编译期已知堆布局 |

已知例外：**引用循环**（A→B→A）不会回收，计数永不归零。
纯 TinyPHP 代码中常见循环是 双向引用/观察者模式——文档化限制，
`--mem-stats` 可在退出时打印 `leaks=N` 量化。树/DAG 结构无此问题。
编译器对最常见的直接自引用（`$o->f = $o`、`$this->f = $this`）给出编译警告，提示潜在泄漏。

## 二、自动回收：引用计数插桩

核心思想：**堆值表达式求值即持有（owned），语句结束释放未转移的持有，
作用域退出释放堆局部变量，容器写经 runtime 钩子转移所有权。**

类型编译期精确已知，插桩无歧义。堆类型：`array<T>` / `map<K,V>` / 类实例 / 接口胖指针。
不插桩：`string`（不可变值 + bump 池，进程回收）、`cstruct`（值语义）、phpc 指针（C 所有）。

| # | 位置 | 规则 |
| - | ---- | ---- |
| R1 | 堆值产生式（new / 函数调用 / 数组字面量） | 求值即持有 refcount≥1 |
| R2 | 赋值 `a = expr` | 求值入临时 → 递减旧 a → 赋值（借用源先递增） |
| R3 | 字段写 `o->f = expr` | 同 R2（self-assign 安全） |
| R4 | 容器写 push/set | runtime 钩子：递增新元素、递减被覆盖/删除元素（按 elem_flags 递归） |
| R5 | 传参 | 实参入临时；形参入口递增（形参拥有自己的引用），函数出口递减 |
| R6 | return | 返回局部变量 = 所有权转移给调用方（作用域清理跳过）；返回字段/元素 = 递增（借用→持有） |
| R7 | 语句结束 | 释放该语句全部 hoist 临时 |
| R8 | 块退出 | 递减本块堆局部（声明逆序） |
| R9 | break / continue | 先递减当前块到循环体的堆局部再跳转 |
| R10 | throw / 函数返回 | 递减全部作用域持有 |
| R11 | foreach 值变量 | 每轮持有元素引用（含接口 obj），迭代尾释放；break/continue 由清理规则覆盖 |
| R12 | 全局 / 静态属性 | immortal——进程生命周期持有 |

`map<K,V>` 与数组同构：`Map` 本身带 refcount（malloc 分配），走 R1–R12 规则；
第一版值槽为**标量或 string**（string 走 bump 池、无 RC），故 map 释放不带嵌套回收
（`tphp_map_free` 释放节点与桶）；堆值 V 在内存模型后续版本随 flags 机制开放。

对象含堆字段时，编译器生成**析构函数**（`tphp_class_X___dtor`）挂在对象头，
计数归零先释放字段再释放对象——嵌套结构（对象持数组、数组持对象/接口）递归回收。

### 可验证性

```console
$ php main.php run app.php --mem-stats
...程序输出...
mem: arrays 17/17 objects 15/15 leaks=0
```

`arrays A/F` = 分配/释放次数；`leaks=0` 表示引用计数正确。
测试架 `tests/run.php` 对**所有用例**编译时开启统计并断言 `leaks=0`——
内存正确性是回归测试的一部分。

### 性能说明

- string 拼接/传参零计数（池语义，与 PHP interned 字符串同思路）
- 整数/bool/浮点/cstruct 零计数
- last-use move 优化（`$a = $b` 后 b 不再用则免递增）留后续版本；
  当前为正确性优先的 uniform 计数

## 三、phpc：显式 unsafe 边界

phpc 是与 C 互操作的唯一通道，类比 Rust 的 `unsafe`：**边界之外依旧安全，
边界之内信任程序员**。C 内存遵循「默认借用 + 显式接管 + 出口自动释放」——
对照：Rust 用 RAII guard（编译器 drop）、Zig 用 defer、V 的 autofree 不覆盖
C 指针；TinyPHP 用所有权登记表 + 编译器在函数出口插 free。全部规则：

| 操作 | 安全性 | 规则 |
| ---- | ---- | ---- |
| `c->符号(...)` 调用 | unsafe | 参数/返回类型不做编译期保证；不经过错误通道 |
| `c->宏` 常量引用 | unsafe | 返回 CVAL（信任程序员） |
| `c_str($s)` | **安全** | string → char* 借用：池内存与进程同寿，指针恒有效；只读 |
| `php_str($p)` | **安全** | char* → string **深拷贝**：C 侧后续 free/修改不影响 |
| `php_str_ref($p)` | 借用 | 零拷贝包装；仅用于生命周期确定的静态数据（getenv/字面量），文档注明悬垂风险 |
| `cbuf($n)` 分配缓冲 | **自动** | 分配即登记，函数所有出口自动 `free`（编译器插桩） |
| `c_own($p)` 接管 C 内存 | **自动** | 登记后函数所有出口自动 `free`——开发者不写 free |
| 未登记的 C 指针 | 借用 | `c->` 返回默认借用（多数 C 返回是静态/借用数据），不释放 |
| 传给 C 的借用 | 调用期有效 | C 侧不得长期持有（无法静态保证） |

CVAL（c-> 返回值）规则：

- 可赋给：`c.*` 标量 / cstruct / 指针 / `int` / `float` / `bool`
- 可用于：数值运算、比较、条件（非零即真）、`c->` 调用的实参
- 不可赋给：`string`（用 `php_str`）/ `array` / 类 / 接口
- **不可推断声明**：`$v = c->foo();` 编译错误——C 类型必须显式声明
  （`c.i32 $v = c->foo();`），这是 PHP 类型自动推导的边界

## 四、类型与内存的交界

- PHP 类型自动推导：`$x = 5;` → int，首次赋值定死；C 侧值（c.\* / cstruct /
  指针 / CVAL）**禁止推断**——与 C 交互的边界必须显式
- cstruct 是 C 的值语义（赋值即结构体拷贝、传参按值）——与 TinyPHP 数组的
  引用语义不同，文档见 `doc/phpc.md`
